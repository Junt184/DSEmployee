# 秘书页立绘素材

由岗位 `layout: 'secretary'` 的页面使用（组装逻辑在 `src/web/script/67-secretary.ts`）。
服务端从 `/assets/secretary/<文件>` 提供，URL 带界面指纹做缓存失效；`/assets/` 是长缓存（immutable）。

## 一、交付形式：**每个状态一张 WebP**（多帧就交一张动图 WebP）

一组的帧由出图那边合成**一张动图 WebP**，客户端只换 `src`。为什么不让客户端逐帧播：
- 一组 6 帧各拉一次请求 vs 动图只拉一次，**帧间压缩**让字节差好几倍；
- JS 切 `src` 会闪（解码来不及），要双缓冲才不闪 —— 浏览器原生已经做好了；
- 少一个定时器就少一类 bug（切页/切员工忘停表 → 两套动作打架）。

**如果你手上是 PNG 帧序列，直接给我就行**，我来合成动图 WebP + 静态图（脚本一行命令，见下）。
命名：`stage-<状态>-<两位序号>.png`（如 `stage-idle-01.png`），并告诉我：**帧率**、**循环还是播一次**。

## 二、要哪些状态（**每个动作 5–7 帧**：3 帧循环太机械）

出图方式是一张张手出（GPT image 2），所以帧数是成本。**按优先级出，出到哪我接哪**。

### 第 1 组 `idle` 眨眼 —— 3 帧 ✅ 已有，可选补到 5 帧
| # | 动作 | 时长 |
|---|---|---|
| 1 | 睁眼（正常） | 2.6s |
| 2 | 半闭 | 0.11s |
| 3 | 闭眼 | 0.09s |
| (4) | *可选*：微闭（睁 → 半闭之间的中间帧） | 0.06s |
| (5) | *可选*：闭 → 睁 的中间帧（略睁） | 0.06s |

眨眼是快动作，3 帧已经能用；补 2 帧会更顺，但**优先级最低**。

### 第 2 组 `typing` 她在敲笔记本 —— **6 帧**（循环，最高优先级 ⭐）
> 用在哪：① 你发了指令、她还没出结果；② 她正在输出文字。这是**最常被看到**的状态。

| # | 动作 | 说明 |
|---|---|---|
| 1 | 低头看笔记本，双手放键盘（手指位置 A） | 循环基准 |
| 2 | 手指抬（位置 B）**身子/头/笔记本不动** | |
| 3 | 手指落（位置 C，左右手错开一点） | |
| 4 | 手指抬（位置 D）+ **眼睛半闭**（眨眼中） | 让循环不死板 |
| 5 | 手指落（位置 E）+ 眼睛睁 | |
| 6 | 手指抬（位置 F）+ **视线略上移到屏幕** | 收尾帧，接回第 1 帧要顺 |

每帧 0.16s（约 6fps）→ 一轮 ≈ 1 秒。**只要手指与视线变，身体、笔记本、构图一律不动。**

### 第 3 组 `notify` 她抬头看你（有新结论）—— **5 帧**（播一次）
> 用在哪：她写进结论时播一次，停 1.4s 后回常态。

| # | 动作 |
|---|---|
| 1 | 低头在笔记本上（与 typing 第 1 帧接近，便于自然过渡） |
| 2 | 抬头到一半（视线离开屏幕） |
| 3 | 抬头看你（正脸、眼神水平） |
| 4 | 同一姿势 + **眼睛亮一点** |
| 5 | 同一姿势 + **嘴角上扬**（"我这儿有东西给你看"） |

### 第 4 组 `listen` 你点输入框时她在听 —— **5 帧**（播一次）
> 用在哪：你点击输入框那一刻播一次，停 0.8s 后回常态。

| # | 动作 |
|---|---|
| 1 | 常态（与 idle 接近） |
| 2 | 身体前倾一点 |
| 3 | 视线转向你 |
| 4 | **轻轻点头** |
| 5 | 同一姿势 + 微笑（"在听你说"） |

### 合计与建议顺序
`3（已有）+ 6 + 5 + 5 = 19 帧`，其中 **16 帧要新出**。

**建议：先只出第 2 组（6 帧）**—— 它一到位我就能接"发指令 → 她开始敲键盘 → 出结果 → 回常态"的联动，
收益最大；第 3、4 组随后补，界面不会因为缺它们而难看（缺图时**退回常态**，不换剪影）。

每个状态再给一张**静态图** `stage-<状态>-still.webp`（取最能代表该状态的一帧），
给"关闭动效"的人用；缺了会退回动图。

**呼吸不占帧**：整幅上下浮 5px 由 CSS 做（4.2s 一循环）。

## 三、硬规格（照这个出就不会返工）

- **同画布、同锚点**：全部 **1024×1536**（或统一别的尺寸，2:3），人物**脚底贴底、水平居中**。
  切图时人物不许跳 —— 这是"帧"能不能用的唯一硬指标；
- **透明底**（不是白底！理由见下），**每个状态合计 ≤ 100KB**：移动端要过网络，还要进 PWA 离线缓存；
  当前 `stage-idle.webp` 是 581×1000 / 2 帧动图 / 135KB；
- 文件名固定、**不带版本号**（缓存失效走界面指纹）；
- 颜色别只靠状态区分：日间/夜间两套主题下都要看得清。

## 三点五、画风决定"要不要透明底"（这条被实测改过一次）

**黑白线稿（当前素材就是）：请保留白底，不要抠。** 因为线稿的线条是近黑的，
抠掉白底后落在夜间主题的舞台上（`#161a22`）对比度只剩 **1.2:1** —— 等于什么都看不见。
实测（同一张图）：

| 处理 | 日间舞台 `#eef1f6` | 夜间舞台 `#161a22` |
|---|---|---|
| 抠掉白底 | 8.0:1 ✅ | **1.2:1 ❌ 看不见** |
| 保留白底 | 8.5:1 ✅ | **8.5:1 ✅** |

所以客户端的做法是：**立绘区做成一张白色画布**（`.secretary-stage { background: #ffffff }`，
两种主题都不跟随），再靠右侧 1px 分隔线 + 轻微纸感内阴影交代边界 ——
让白底看起来是**故意的**（一张画布），而不是漏出来的一块白。
素材侧只需保证：**四角是纯白**（当前素材实测四角 (254–255) ✅）、人物别贴到画布边缘。

**彩色厚涂 / 照片类素材：反过来用透明底**。那时人物本身有明暗，浮在主题色上没有白板边界问题，
而且能跟随日/夜氛围。判断标准很简单：

- 人物像素**几乎没有彩度**（当前素材：0.0% 有彩度、9.3% 近黑、84.4% 近白）→ **线稿 → 保留白底**；
- 人物本身有色彩与明暗 → **透明底**。

## 四、合成命令## 四、合成命令（我这边跑，PNG 序列 → 动图 WebP + 静态图）

```bash
python3 - <<'PY'
from PIL import Image
frames = [Image.open(f'stage-idle-{i:02d}.png').convert('RGBA') for i in range(1, 7)]
frames[0].save('stage-idle.webp', 'WEBP', save_all=True, append_images=frames[1:],
               duration=1000//6, loop=0, quality=85, method=6)
frames[0].save('stage-idle-still.webp', 'WEBP', quality=85, method=6)
PY
```

- **帧源图不入库**：PNG 帧序列放在仓库根下的**本地素材目录**里（`<素材目录>/生成-第2组-敲键盘/`、
  `<素材目录>/生成-第3组-抬头看/`，第 1 帧就是 `低头看笔记本.png` 本身），本目录只收合成好的 WebP。
  那个目录由 `.gitignore` 挡住，不进版本库。
- **`still` 取哪一帧**：`typing` 取第 1 帧（低头敲键盘的常态）；`notify` 取末帧（抬头看你，即
  `holdMs` 期间停住的那个姿势）；`standby` 取 K01-C（坐在木椅上的标准翘腿姿势）。
- **画布与切换**：`idle` 是 601×1000（裁到人物），`typing/notify/standby` 是 1024×1536（2:3，
  正好等于 `.stage-art` 的 `aspect-ratio`）。`standby` 已从横向趴姿换成竖向木椅坐姿，人物与椅子完整入画；
  切状态仍由 `object-fit: contain` + 交叉淡化保证不变形、不白闪。
- **接线已经接好**（`67-secretary.ts` 的「立绘与真实的联动」一节 + `65-chat.ts` 两个调用点）：
  回合起止 → `stageTurn`（thinking / 回 idle + 读了新结论就 notify）、开始吐字 → `stageSpeaking`、
  点输入框或闲着 30 秒 → `standby`。**只在她这一页上动**（`stageOnScreen`），历史回放绝不碰立绘。
- **`standby` 这一组的构成（2026-09-24 重做）**：木质椅子坐姿 + 翘二郎腿；呼吸（K01–K06）→ 眨眼（K07–K10）
  → 手指微动（K17–K20）→ 视线向右（K21–K24）。按审核结论，视线向左 K11–K16 整组弃用；没有把 A/B/C/D
  候选混成连续帧，而是每个 K 只选一张，再按慢节奏插入 50% 过渡帧。眨眼三段不插混合帧，避免重影。
- **坐姿版节奏**：使用慢速 + 过渡帧；最终预览与候选选择记录在 `<素材目录>/生成-第5组-木椅翘腿-候选帧/最终选定帧-待命动画/`。
  只有 K01–K10、K17–K24 进入最终动画；K11–K16 视线向左按审核结论弃用。

- **旧趴姿版本节奏记录**（仅作历史参考，当前 `stage-standby.webp` 已替换）：
  - **慢**：平均每帧 666ms、一轮 18.6–20.2 秒。第一版是每帧 203ms、一轮 6.7 秒 ——
    实测"每秒切 5 次姿势"，看起来就是整个人在抖（用户原话：像瞎几把播放）。
    参照物是已经认可的 `idle`：2.6 秒常态 + 0.1 秒眨眼 = **大部分时间静止，偶尔动一下**。
  - **过渡帧**：换姿势前插一张 50% 混合帧（80ms），**眨眼段不插**（眨眼要脆）；
    回到常态/离开常态也要插 —— 那是"她动完 settle 回去"的过程，最需要过渡。
- **一个必须记住的教训（GPT 出图的物理限制）**：这些帧**不是"只改了眼睛/脚"**，
  而是模型把整个人重画了一遍 —— 实测把基础图自己平移 1px，差异就有 6.45–8.03%，
  和真实帧之间的差异（5.6–8.2%）完全同量级；想做"只搬变化区域"的局部合成，
  两种定位方法都失败（差分集中在整个人物上）。所以**唯一的出路就是节奏 + 过渡帧**，
  别再指望"逐帧只动一处"。
- **为什么没有「脚尖下勾」这一拍**：GPT 出图在这个趴姿下画不出生理结构正确的那只脚。
  试过 6 种写法都崩（`the toes point downward` / `relaxed and pointing down` / 去掉线稿约束让它
  出彩色动漫图再转回线稿的两段式），所以这一拍直接删掉 —— 脚的部分只保留「抬起」的 4 拍。
  教训：**"抬脚/勾脚"这类需要模型重画肢体的动作，在单图参考的出图方式下不可靠；
  手指、视线、表情、头部这些"局部小改"才稳。**
- 素材没到位时页面不会破图：**自动降级成手绘剪影**，并写明缺哪个文件。
