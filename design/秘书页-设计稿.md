# 秘书页（galgame 风）设计稿

> 状态：**设计冻结**，可开工。本文只描述这一页的**壳与契约**；横切行为（流式、附件、会话、断线、
> IME、安全区、主题、动效偏好）一律复用现有对话页的实现，不复制第二份。
>
> 放在 `design/` 而不是 `docs/`：`docs/` 只存本地、不入库（见 `.gitignore`），这份是产品侧
> 设计稿，进仓库是对的。

## 0. 一句话

给「秘书」岗位一个**专用对话页**：左立绘、右对话（气泡区 + galgame 对话框），顶部一个下拉箭头，
拉下来是全屏「上次结论」看板。手机降级成立绘当背景。

## 1. 已冻结的决定

| # | 决定 | 说明 |
|---|---|---|
| 1 | 气泡区在**底部**、紧贴对话框上方，**独立滚动区** | 长对话只滚气泡，不带动整页 |
| 2 | 两栏门槛 **≥960px**（立绘 38% / 对话 62%）；641–959 与 ≤640 立绘当背景 | 沿用现有断点风格 |
| 3 | 下拉箭头：拉下来是**「上次结论」**，**覆盖式** | 她输出一次结论就覆盖一份；**从没输出过就是空白** |
| 4 | 看板不区分"今日/近期"，就是她最近一次写进去的东西 | — |
| 5 | 立绘**只做一套**，秘书岗位只挂一个员工，共用 | 不做"每员工一张脸" |
| 6 | **要打字机效果** | 见 §5：必须自适应，不许追不上真实流式 |
| 7 | 点击对话框的特效作用在**立绘**上（立绘反应） | 输入框只做常规聚焦反馈 |
| 8 | 布局与槽位做成通用机制（岗位声明 `layout`），**不写第二套对话页** | 见 §8 与「失控」三对策 |
| 9 | 不要声音 | 顺带：现有 CSP `default-src 'none'` 没有 `media-src`，加声音要改策略 |
| 10 | 母语用词：这一页对着的用户是"我"，秘书是"她" | 文案一律第二人称给出："她还没写过结论" |

## 2. 布局规格

```
桌面 ≥960px                                 手机 ≤640px（降级）
┌───────────────┬────────────────────┐      ┌──────────────────────┐
│               │      ▽  下拉箭头     │      │        ▽             │
│     立绘       ├────────────────────┤      ├──────────────────────┤
│   (左栏 38%)   │  气泡区（独立滚动）    │      │  气泡区（半透明底）      │
│               │                    │      │   ─ 立绘作为该区背景 ─   │
│               ├────────────────────┤      ├──────────────────────┤
│               │  galgame 对话框      │      │  galgame 对话框        │
└───────────────┴────────────────────┘      └──────────────────────┘
```

- **立绘**：`stage` 槽位，垂直居中偏下（脚底贴底、头顶留白 8%）；桌面显示宽约 420px。
- **气泡区**：`overflow-y: auto`，独立滚动；顶部留 12px 渐隐遮罩（避免文字被箭头压住）。
- **对话框**：galgame 文本框样式（圆角、半透明底、左上姓名牌「秘书名 + 状态」）；📎/发送/停止等**沿用现有控件**，只是换了外框。
- **下拉箭头**：右栏顶部居中；**常驻**（有内容时带小点与"更新于 …"），拉下来是全屏看板（§4）。
- **手机**：立绘 `position: sticky` 作为气泡区背景，加 `mask` 渐隐 + 气泡半透明底（保证可读性）；
  看板本来就是全屏，无需改动；对话框贴底并处理安全区（沿用 `max()` 写法）。
- **动效偏好**：`prefers-reduced-motion: reduce` 下关掉呼吸/眨眼/打字机/点击特效，**状态改用文字与颜色表达**（不许把信息只放在动画里）。

  `stage`（立绘）/ `board`（看板内容）/ `rail`（右侧常驻栏，默认）。

## 4. 「上次结论」看板（覆盖式）

**语义**：她每次产出结论时**覆盖**写一份；看板永远显示最近一次那份；从没写过 → 空白（如实说明，不是"没有内容"这句含糊话）。

**文件契约**（她维护，控制台只读）：

- 路径：`memory/ref/结论.md`
- 首行必须自带时间戳，格式固定：`<!-- 更新于 2026-09-23 19:05 -->`
  **为什么时间戳要写进文件**：`employee.files.list` / `files.get` **只回 `{path, type, size}`，没有 mtime**
  （`src/node/employees.ts` 的 `listFiles`）。拿不到 mtime 就没法判断"这份结论有多旧"，
  而"看起来没问题的旧数据"正是本项目最防的一类失败。改协议加 mtime 代价大（动节点与协议），
  写进文件零成本。
- 正文：markdown，控制台按**已有子集**渲染（代码围栏、行内代码、加粗、列表、链接）。
  ⚠️ 现有渲染器**不支持 `#` 标题**——她若用标题，会显示成字面量。两个选择：让她不用标题（推荐，改用加粗行），
  或给渲染器补标题支持（约 10 行，P2 里做，二选一）。
- 陈旧规则：超过 7 天 → 顶部挂黄字"结论更新于 N 天前"；文件不存在 → "她还没写过结论"（空态）。

**箭头与看板交互**：常驻箭头 → 点击 → 全屏面板从顶部**下铺**（`transform: translateY` + 300ms）；
关闭：右上 ✕、Esc、上滑；铺开时输入框被盖住是**有意的**（看板是"读"模式）。

## 5. 打字机（要，但要自适应）

**问题**：真实流式的 delta 是**变速**到达的（可能几十毫秒一条，也可能一次一大段）。
固定速率打字机会在长回复上永远追不上，看起来像卡住 —— 这是 H5 对话游戏里不存在的问题（那边文本是预设的）。

**做法**（接到现有机制上：`appendDelta` → `ensureStreamBubble` → `refreshStreamText`；定稿走 `finalizeStream` → `renderMarkdown`）：

1. `appendDelta` 不直接写 DOM，而是把文本推进**每个气泡自己的队列** `pending`；
2. 用一个 rAF 循环吐字：每帧吐 `k` 个字符，`k = clamp(ceil(积压 / 12), 1, 8)`
   —— 积压越多吐得越快（60fps 下最高约 480 字/秒），**永远追得上**；
3. 队列空 → 停止循环（不留常驻定时器）；
4. **定稿必须 flush**：`finalizeStream` 把剩余队列在 ~150ms 内加速吐完，然后才 `renderMarkdown` 重排
   （重排只在定稿后做 —— 这是现有约定：流式期间是纯文本，避免每几十毫秒重排一次 markdown 造成闪烁）；
5. **点击气泡立即全显**（对话游戏的标准"跳过"）；切会话 / 切员工 / `breakStream()` / 页面隐藏 → 立即 flush，不留半截；
6. `prefers-reduced-motion: reduce` → 直接全文显示，不走打字机。

**已知取舍**：打字机期间 markdown 不渲染（与现状一致），所以 `**加粗**` 会在吐完之后才变成粗体。
这是刻意的：逐字打的时候反复重排 markdown 会闪。

## 6. 立绘与状态

**素材形式：部件式帧图 + SVG 叠加**（不做整帧序列，字节差一个量级）。

**画布：900 × 1350（@2x）**，桌面左栏显示约 420×630；手机用同一套（或另给竖屏裁切版）。

| 文件名 | 内容 | 用在哪 | 必要性 |
|---|---|---|---|
| `body-base.png` | 身体 + 头发 + 服装（**不含**眼/嘴/手臂） | 常驻底层 | 必需 |
| `eyes-open.png` / `eyes-half.png` / `eyes-closed.png` | 眼睛三态 | 眨眼、思考时左右看 | 必需 |
| `mouth-closed.png` / `mouth-half.png` / `mouth-open.png` | 嘴三态 | 说话循环 | 必需 |
| `brow-calm.png` / `brow-focus.png` | 眉两态 | 思考态 | 可选 |
| `arm-idle.png` / `arm-raise.png` | 手臂/手势 | 推送结论时"递给你" | 可选 |
| `mobile-stage.png` | 竖屏裁切特写 | 手机当背景 | 可选（也可用同一张 + 蒙版） |

**硬规格**：
- PNG 或 WebP、**透明底**、**每张都是 900×1350、部件位置与最终合成完全一致**（别裁剪导出 ——
  裁剪版我就得跟你对坐标表，容易错；而大片透明的 PNG 压得很小，字节差不了多少）；
- 命名固定、**不带版本号**（缓存失效走界面指纹）；
- **总量 ≤400KB**（要过网络、要进 PWA 离线缓存）；
- 颜色**不要只靠状态区分**：浅色/深色两套主题下都要能看；需要换色就给两套，或交给我用 SVG 上色；
- 确认可商用（要进仓库）。

**五个状态**（我给你状态机，你给图）：

| 状态 | 触发 | 组成 |
|---|---|---|
| `idle` | 默认 | 呼吸（身体 1.5% 缩放，4s 循环）+ 随机眨眼（3–6s 一次，三态切换） |
| `thinking` | 你发出指令、她还没出结果 | `brow-focus` + 眼睛缓慢左右看（2s 一个来回） |
| `speaking` | 她正在流式输出（与打字机同步） | 嘴三态循环（约 8fps，队列空时停） |
| `notify` | 有新的「上次结论」写进来 | 一次性 800ms：抬眼 + SVG 光晕 |
| `click` | 你点对话框 | 一次性 600ms：前倾 + 微笑（`brow-calm` + 嘴慢速一次） |

**我负责的 SVG 部分**（不用你画）：下拉箭头、光晕与粒子、姓名牌、看板卡片边框与分隔、主题适配、
以及关掉动效时的静态降级。

## 7. 点击特效

点对话框（聚焦输入）→ 给页面加 `is-composing` 类 → 立绘播一次 `click` 状态 + SVG 光晕扩散。
三条硬约束：

1. **不许挡输入**：点击到能打字 ≤150ms，动画只是视觉反馈，不能等它播完才 `focus()`；
2. **必须尊重 `prefers-reduced-motion`**（控制台已有两处先例）；
3. **一次性动画必须有终点**，播完即停，不留常驻动画耗电。

手机额外一条：动画不能和键盘弹起打架（现有 `interactive-widget=resizes-content` 已在用）。

## 9. 风险与对策

| 风险 | 现状证据 | 对策 |

## 10. 明确不做（记录以防反复）

- 不做 Live2D / Spine / Rive / Lottie（要引运行时，与"零构建 + CSP `script-src 'self'`"冲突）；
- 不做语音、不做音效（CSP 还要开 `media-src`）；
- 不做"每员工一张脸"（秘书岗位只有一个员工）；
- 不做看板的多份历史（**覆盖式**是她定的语义）；
- 不改协议加 mtime（时间戳写进文件内容）。
