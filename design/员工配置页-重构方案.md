# 员工配置页重构方案

日期：2026-10-07。基于当前仓库代码分析；原型使用示例数据，不代表线上状态。方案已获确认并落地仓库源码，新增批量设置模型；按用户要求不运行测试，尚未部署线上。

## 为什么现在不好用

1. **先展示基础设施，后展示员工。** `src/web/markup.ts` 的 `viewLlm` 顺序为「端点库 → 节点权限档位 → 员工的模型」。用户想给某位员工换模型，却要先穿过共享资源和整机设置；三种作用范围混在一页，操作前还得判断会改谁。
2. **员工信息分散。** 姓名、岗位、分组、初始提示词、头像在办公区工位编辑器里；模型、自动审批在员工配置页里。当前「员工配置」实际仍以模型为中心，名字和内容不一致。
3. **长列表套编辑器，缺少稳定焦点。** 每位员工都可展开，多位同时展开后，模型行、添加表单、说明、删除按钮混在一起。没有员工搜索与固定的当前员工标题，员工多时难找、难比较，也容易改错人。
4. **表单依赖占位文字，操作权重相近。** 端点与模型表单主要靠 placeholder 说明字段；输入后字段名消失。新增模型表单一直占空间，「保存」「保存并设为当前」同时为主按钮；删除、清空和日常动作距离过近。
5. **系统说明替代了操作指引。** 页面直接展示 BaseURL、scope、路由、接线等概念，解释文字又长。纯文本里的 `**` 没有 Markdown 渲染，会直接出现在页面上。用户需要的是当前值、生效范围和下一步。
6. **编辑过程缺少稳定性。** `renderLlmConfig()` 清空并重建所有员工行。`loadLlmDetail()` 与 `loadPermissionPreset()` 的独立异步响应都会触发全量重绘；一个配置请求结束可能重建另一位员工正在填写的表单。草稿没有独立状态，存在输入丢失风险。
7. **失败和生效反馈不完整。** `loadLlmDetail()` 失败仅报告错误，没有写入详情失败状态，区域可能一直显示「正在读配置」。`saveModel()` 调用 `loadLlmDetail()` 后立即调用 `activateCurrentSessionIfOpen()`，而前者刚删除详情缓存，后者找不到当前模型就返回；代码中的“保存并设为当前后切换当前会话”流程可能被跳过。这是静态代码发现，尚未运行验证。

## 推荐结构

保留一级导航「员工配置」，页面内分为三个入口：

- **员工设置（默认）**：左侧员工选择，右侧仅展示当前员工。员工列表显示姓名（岗位）、分组与节点状态，支持按姓名/岗位搜索；选中项持续高亮。
- **模型服务**：原端点库。集中管理服务名称、接口地址、密钥、代理、可选模型和被哪些员工使用。修改共享服务时明确展示受影响员工；员工绑定模型时可就地新增服务，保存后返回原表单并自动选中它。
- **节点设置**：整机默认权限。按节点展示，明确“影响该节点所有员工之后新建的会话”。只有具备 `node.admin` 的设备显示可写入口；无权限时显示必要的只读说明。

默认进入员工设置，优先选上次在配置页查看的员工；首次进入可承接当前对话员工，否则选首位可用员工。配置选择使用独立 `configEmployeeId`，不修改对话里的 `selectedEmployeeId`，防止后台聊天上下文被切走。

## 当前员工的右侧内容

顶部一直显示头像、姓名（岗位）、分组、所属节点及在线状态。下方只保留三个平级分区，默认进入「模型」：

### 模型

- 先显示“新会话默认模型”，使用用户看得懂的别名，并补充服务名称与实际模型 ID。
- 再显示已添加模型。每行突出别名与当前标记；常用动作是「设为默认」，改名和删除收进更多操作。已有模型比较和切换无需打开表单。
- 仅点击「添加模型」时展开就地表单，顺序为“模型服务 → 模型 → 显示名称”。显示名称可给建议值，用户改过后保持原值。
- 一个主按钮「添加模型」，可选勾选「同时设为默认」。避免两个主按钮竞争。
- 生效范围单独说明：新会话使用默认模型；本控制台当前打开的该员工会话，提供明确的「同时切换当前会话」选项。不改其他历史会话。运行中的会话显示“本回合结束后可手动切换”，除非实现了持久化延后任务，不承诺自动等待或自动切换。
- 保存结果分开显示“模型配置已保存”和“当前会话已切换/未切换及原因”，不能用一个“成功”覆盖部分失败。

### 基本信息

- 姓名、岗位、分组、初始提示词收敛到这里，与办公区编辑入口共用同一组件和校验。
- 头像可在顶部进入就地编辑；工作区与运行节点先只读，当前系统没有迁移接口，不提供伪编辑控件。
- 提示词明确“新会话生效”，与岗位说明、知识库区分。
- 「注销员工」放在底部折叠的管理操作中，明确保留工作区。常规编辑使用单独的「保存基本信息」。

### 审批与权限

- 可编辑项只有该员工的「自动通过审批」，与读取到的会话权限分区展示。
- 自动审批说明保持简短：“审批自动通过，提问仍需回答；文件访问范围由会话权限决定。”不能暗示关闭后每个工具都必然审批。
- 会话权限只读标记“最近会话记录”，展示会话名称/时间；没有会话、读取失败和未知值分别显示，不能把未知当默认。
- 节点默认权限作为只读来源说明，并提供进入「节点设置」的链接，不在员工表单里混入整机开关。

## 必须一起修的交互契约

1. **草稿独立于 DOM**：按员工与表单保存普通字段草稿。切换员工、切标签、后台更新不丢输入；密钥仅在当前页面内存短暂保留，不进 localStorage、调试日志或原型状态。
2. **局部更新**：员工列表、详情加载状态、只读权限、编辑表单分开渲染。请求返回只更新所属区域，不替换正在输入的节点，不抢焦点、不跳滚动位置。
3. **异步隔离**：每位员工独立请求版本；迟到响应不能覆盖新选择、已保存配置或已修改草稿。服务探测结果与该次地址/代理/凭据版本绑定，避免旧结果串入新表单。
4. **真实状态**：分别显示首次加载、刷新中、离线、无权限、失败、空配置。失败保留已读数据与草稿，并就地提供重试；离线员工允许查看已有快照，必须在线的写操作注明原因。
5. **完整操作生命周期**：提交防重复；失败恢复按钮和输入；字段错误贴近字段。代理端口校验失败时不能让「获取模型列表」永久禁用。只有请求被确认后更新已保存值。
6. **明确作用范围**：共享服务保存显示影响名单与逐员工同步结果；部分失败保持可见并支持只重试失败项。当前模型与会话实际模型分别展示，不能从员工默认值推断某个历史会话已经切换。
7. **手机布局**：顶部员工选择器代替长侧栏，选择员工后直接进入详情；分区切换保持可见，表单单列。保留足够触控面积，不把桌面多列行压成小字。
8. **无障碍**：字段有持久可见 label，选中状态有文字/语义；可用键盘完成选择、编辑和保存。错误与保存结果通过适当的 live region 提示，状态不只靠颜色。

## 建议落地顺序

1. 拆分页面内三个入口，建立员工选择与详情骨架；优先重构模型区域，加入固定字段名、按需添加和明确生效范围。
2. 接入独立草稿、局部渲染与请求版本，修复读取失败状态、保存后会话切换和提交失败恢复。它们与布局一起交付，才能真正改善手感。
3. 收敛基本信息与审批入口，最后完善共享服务影响范围、同步失败处理与手机布局。

实现时可保留对外视图键 `llm` 和现有 RPC 契约，避免破坏已保存的页面恢复。建议将 `40-pages.ts` 中的模型服务、节点权限与员工详情按职责拆成脚本片段，由 `ui.ts` 显式拼接；不要只在原大函数里继续叠分支。

本次可点击原型覆盖：员工选择、分区切换、模型添加与设默认、基本信息草稿保留、审批设置、共享服务与节点设置。所有操作只影响原型中的示例数据。

## 实现记录与批量设置模型

- 员工、共享服务、节点权限分别放入 `43-employee-config.ts`、`41-model-services.ts`、`42-node-settings.ts`；`44-batch-models.ts` 管理批量流程。办公区的编辑入口跳到统一基本信息表单。
- 批量界面支持姓名/岗位/分组筛选，多选、全选筛选结果、仅选在线员工。统一选择服务、模型和显示名称，可勾选设为新会话默认，以及同时切换本控制台当前打开的该员工会话。
- 同一服务与模型复用已有记录的 id 和名称，并通过 Hub 更新服务配置，保证当前地址与凭据被下发；其他模型、其他历史会话保留。
- 两位员工并行处理，每位员工在执行期间锁定本控制台的配置写操作。目标、参数和当前会话在开始时拍快照，后续筛选和页面切换不改变已开始的任务。
- 逐员工展示成功、离线、命名冲突、连接未完成、当前会话未切换等结果。可重试一位失败员工或所有失败员工，不重复处理已成功员工。
- 请求结果不确定时保留保存请求的幂等键；重试前先读取已保存的绑定，若已存在则复用 id，避免重复新增。运行中的会话不会自动等待；结束后显式重试切换。
- 服务编辑器独立挂载，探测结果绑定本次地址/凭据/代理版本。共享服务同步部分失败时保留逐人结果，并支持只重试失败员工。
- 草稿只保存在页面内存中；刷新页面不恢复未保存输入，密钥不写入浏览器持久存储。配置员工选择按 Hub 保存，与聊天员工选择独立。
