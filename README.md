# DSEmployee

[English](README-en.md) | **简体中文**

**基于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）的数字员工平台。**

dsh 本身是一个完整的 Agent 运行时，但它只管单机、不管"谁能访问"。DSEmployee 在它之上
补了四件事——**认证、跨机、目录、授权**——把分散在各台电脑上的 dsh 工作区变成一个
可以被集中指挥的数字员工团队：

> **一个数字员工 ≡ 一个 dsh 工作区。**
> 岗位说明书与知识库是工作区里的 `AGENTS.md`（dsh 每次会话自动注入），专属技能是
> `<工作区>/.dsh/skills/`，对话框是该工作区下的 dsh 会话，自定义模型端点是
> `.dsemployee/llm.json`，自定义头像是 `.dsemployee/avatar.*`。
> 员工身份随目录走：整个目录拷到另一台机器，他还是他。

角色分工：**Hub**（一台服务器）负责认证、目录聚合、授权与中转；**终端节点**
（公司 Mac、家里 Windows……）各自托管本机 dsh 并承载员工；**授权设备**
（手机/电脑的浏览器控制台、CLI、脚本）经 Hub 给任意员工下达指令。

---

## 架构

```
                 ┌──────────── 服务器（1 台）────────────┐
   浏览器控制台   │  Hub                                  │
   （手机/电脑）  │   单端口：HTTP 控制台 + WS 控制面       │
        │        │   认证：Ed25519 挑战签名 + 配对码/审批  │
        │ 出站    │   目录：跨终端员工注册表（全量替换）     │
        ▼        │   授权：互调 ACL + 审批中心             │
        └───────▶│   中转：路由 + 对话离线邮箱          │
                 └────▲─────────────────▲────────────────┘
                      │ 终端主动出站     │ 终端主动出站
              ┌───────┴───────┐  ┌──────┴────────┐
              │ 终端 A         │  │ 终端 B         │
              │  node-agent    │  │  node-agent    │
              │   ├ dsh（只听回环）│   ├ dsh（只听回环）│
              │   ├ 员工 小艾   │  │   ├ 员工 阿澈   │
              │   └ 员工 …      │  │   └ …          │
              └────────────────┘  └────────────────┘
```

**终端主动出站连 Hub**，Hub 不需要能反向连终端——没有内网穿透需求；**dsh 永远只监听
回环**，只有同机的 node-agent 能驱动它，外部流量全部由 Hub 收敛。

关键机制，各一段：

- **员工 = 工作区**：节点扫描员工根目录下含 `.dsemployee/employee.json` 的目录得到员工
  清单，全量上报 Hub（删目录即自然收敛，不留幽灵条目）。`AGENTS.md` 是岗位说明书，
  dsh 每次会话自动注入；`<工作区>/.dsh/skills/` 是该员工的专属技能（rank 100，优先级最高）。
- **认证与配对引导**：设备身份是浏览器/CLI 生成的 Ed25519 密钥对（私钥不可导出），
  `deviceId = sha256(SPKI DER)`；握手 = 一次性 nonce 挑战签名 + 有界设备令牌（Hub 只存
  sha256）。新设备的授权主路径是 **6 位配对码**（Hub 启动打印 / `dse pair-code` 生成，
  终端节点也能出码就近授权），或任一已授权控制台在「设备」卡片里页面内批准；兜底是
  Hub 本机 `dse pair approve`。批准后无需搬运令牌——设备下次握手时自行领取。
- **员工级模型端点**：每个员工可单独配 OpenAI 兼容端点（API URL + Key + 模型）。
  配置存工作区 `.dsemployee/llm.json`（0o600，apiKey 不出节点、接口只回掩码）；
  保存时节点把它接线到 dsh——按员工声明 `dse-emp-<id>` 的 pi-ai provider 路由 +
  凭据，新建会话自动 `session.selectModel` 到该路由；已存在的会话不迁移。
- **互调 ACL + 审批**：员工之间可以互调（`employee.invoke`），受 `from/to/effect`
  规则约束；命中 `approve` 规则的调用进审批中心，由控制台裁决后执行。
- **RPC 幂等重试**：方法表标记 `idempotent: true` 的请求必须带 `idempotencyKey`；Hub 按设备、key、方法与规范化参数摘要持久化执行预约和响应。同一请求重放返回原响应，参数不一致会被拒绝。缓存保留 24 小时并受总量上限约束；Hub 崩溃留下未完成预约时会报告结果不确定并拒绝自动重跑，避免可能的重复副作用。这不是跨外部系统的 exactly-once 事务。
- **无人值守审批与提问**：员工跑在没人在的机器上时，dsh 自己的审批闸会 fail-closed
  （那一轮一直挂着直到被中止）。节点把 dsh 的 `approval/requested` / `question/requested`
  抬进 Hub 审批中心，控制台批准（或回答问题）后原路回填给 dsh，卡住的那一步当场继续。
  提问以结构性选择卡片呈现，答案原样回填——**Hub 不解释它的形状**。
- **节点离线时对话指令与异步互调可排队**：`session.prompt` 在目标节点离线时会进入 Hub 邮箱，节点重连后按序投递；
  `employee.invoke` 会以异步委派形式入队，节点上线后先确认接收，再通过 `employee.invoke.settle` 回报最终结果；
  队列每节点最多 50 条、最长 24 小时，过期或队列满会如实提示。投递结果未知时最多尝试 3 次后停下，
  避免员工收到重复指令。其他需要立即拿到返回值的方法（例如创建会话、员工互调）仍立即返回 `node-offline`，
  不会假装成功。该机制不是 exactly-once；体检页会显示仍留在邮箱里的条目。
- **连接健壮性**：两条活性层。应用层 tick（Hub 每 15s 一帧）供客户端看门狗判活
  （控制台与节点共用逻辑：2.5 个间隔无帧即判半开、断开重连）；传输层 ping/pong
  由 Hub 主动清扫（两次未 pong 即 terminate）。同一 nodeId 重连时旧连接被立即淘汰，
  转发永远落在新连接上——公网反代下的半开连接不会变成"看不见的僵尸"。
- **反代部署（trust-proxy）**：Hub 默认只信 TCP 对端 IP；前面有受控 nginx/caddy 反代时
  加 `--trust-proxy`，客户端 IP 改从 `X-Real-IP`/`X-Forwarded-For` 取，保住节点配对的
  回环判定语义。直连部署开了反而引入伪造面。

## 快速开始

前置：Node ≥ 22.19，本机已安装 `dsh`（`npm i -g @deepseek-ai/dsh`）。

```bash
npm install
npm run build          # 或开发期直接用 bin/dse.mjs（Node 原生剥离 TS 类型）
```

### 1. 在服务器上启动 Hub

```bash
node bin/dse.mjs hub --port 19790
```

输出会给出控制台地址、控制面 WS 地址，以及一个 **6 位配对码**（24h 有效、一次性）：

```
  ╔══════════════════════════════╗
  ║   配对码（24h 有效）：482913   ║
  ╚══════════════════════════════╝
```

### 2. 在终端电脑上启动节点

```bash
node bin/dse.mjs node \
  --hub ws://<服务器IP>:19790/ws \
  --name 办公PC \
  --employee-root D:\Employees \
  --dsh-home D:\Employees\.dsh \
  --dsh-env DEEPSEEK_API_KEY=sk-xxxx
```

节点会：拉起本机 `dsh --profile web`（只监听回环）→ 扫描员工工作区 → 连上 Hub 上报目录。
回环首连的节点（未索要任何 scope）会自动获批；否则在 Hub 上产生一条待审批请求——
**节点会一直等着，批准后自动连上，无需重启**。

> **模型凭据必须给**：不给 `--dsh-env DEEPSEEK_API_KEY=…`（也没在该 DSH_HOME 的 dsh Web
> 「Models」页面里写入）时，员工能连上、能建会话，但**一执行任务就会以 `MISSING_CREDENTIAL` 失败**。
> 这条错误会一路回传到调用方，不会被吞掉——这是刻意设计，免得失败表现成"跑完了但没结果"。

### 3. 授权你的第一台设备（配对码）

打开控制台（第 4 步），它会自动生成设备身份并发起配对——页面停在授权页时，
输入 Hub 启动输出里的配对码，点「使用配对码授权」，完事。

Hub 在云服务器上（看启动输出要 SSH）时，**任一终端节点也能出码**——在手边的终端执行
（用本机节点身份上报，10 分钟内有效，并会弹桌面通知）：

```bash
node bin/dse.mjs pair-code --hub ws://<服务器地址>:19790/ws --label 公司Mac
```

配对码过期或找不到，在 Hub 本机重新生成（旧码作废，运行中的 Hub 立即认新码）：

```bash
node bin/dse.mjs pair-code
```

> **信任模型一句话**：Hub 码等价于"能看到 Hub 终端输出的人"；节点码等价于"能操作一台
> 已配对终端的人"——后者本来就持有能驱动其全部员工的节点身份，给它出码权不扩大攻击面。
> 所有码只存 sha256、用一次即作废；节点码最多活 30 分钟、每节点最多 3 个活跃码；
> 输错 5 次该 IP 会被短暂拒绝。

**兜底路径**（配对码不可用时）：Hub 本机直接批准——

```bash
node bin/dse.mjs pair list               # 看谁在申请配对
node bin/dse.mjs pair approve <requestId> --name 我的手机
```

> 这条命令在本机直接改状态文件、不走网络，信任锚是"能读写 Hub 状态文件的人本来就已
> 控制这台机器"——比任何"首次连接自动放行"的魔法更可审计。**批准后不需要搬运任何
> 令牌**：设备下次连接时自行领取（它能签出挑战就证明了它是它）。令牌弄丢了在 Hub 本机
> `dse token rotate <deviceId>` 轮换；是本机 CLI 的话新令牌自动写回本地。

### 4. 打开控制台

浏览器访问 Hub 的地址。控制台自动生成 Ed25519 设备密钥（私钥不可导出、存 IndexedDB）、
自动连接；首次进入停在授权页，输入配对码即可，之后每次打开自动登录。

控制台同时是一个 PWA：iPhone 上用 Safari「分享 → 添加到主屏幕」（安卓 Chrome 会直接
给安装提示），之后从主屏幕图标进入就是独立窗口的全屏体验。service worker 只做静态壳缓存
（页面/脚本/图标）且**一律网络优先**，缓存仅作离线兜底；控制面 WS 与 `/api` 永远直连 Hub、
不进缓存。脚本地址带内容指纹（`/ui.js?v=<指纹>`），SW 的缓存名与 precache 由同一指纹派生，
所以**改一行前端代码就会自动换代**：客户端下次打开即自愈，不需要人记得升版本号，也不会出现
"电脑上对、手机上还停在旧脚本"的错配。页面会印出当前脚本指纹，与服务端不一致时自动标红
（机制见 `docs/03` §3.8）。

> 工位布局有两套：宽屏是「头像 | 小屏」两栏横排（头像是视觉主体，110px）；**窄屏
> （≤900px，手机）改竖排** —— 头像占左列跨两行、右侧上名字下状态，**小屏独占整行**吃满
> 卡宽。手机上卡片只有 161–163px 宽，横排会把实时输出压到 47px（5 个汉字/行），竖排后是
> 143–149px（15–18 字/行）；文字会溢出时优先保小屏，名字/状态改为上下排（实测数字见
> `docs/05` §13.5）。

控制台的主页是**办公区**：按员工分组分区，每个员工一个像素工位（默认头像是按员工 id
确定性生成的 8-bit 像素小人；忙碌时徽章呼吸、桌上显示器滚屏显示实时输出、有新输出且
你不在他对话框时亮未读红点）。点工位进入与该员工的对话框。顶部标签切到**模型配置**页
可以给单个员工配模型端点；工位名牌下的「换头像」可以上传自定义头像（png/webp/gif/jpeg，
≤2MB），「恢复默认」回到像素小人。

刷新或重新打开控制台会恢复上次所在页面，以及每位员工上次打开的会话。读取失败会保留
已经显示的消息并提供重试；读取历史期间收到的新输出会按会话事件序号合并，向上阅读时
不会被新输出拉回底部，可点「回到最新」恢复跟随。

回合失败会区分本次输出与历史记录，并显示原始发生时间（记录里有时间时）。已知的模型
认证、限流、超时和暂时不可用错误会给出中文说明；「错误详情」保留原始错误码和文案。

「员工与会话」默认只列出所有员工，高亮当前员工，名字右侧显示（岗位名称）；每位员工
下面的会话默认收起，点击该员工的箭头才展开。普通对话、秘书、渗透测试、安全监测和
应急响应共用左侧导航，岗位专属工作区保持各自布局。宽屏（≥1200px）默认常驻，收起后
保留窄栏入口与当前员工头像；窄屏从同一入口打开左侧抽屉，支持点击遮罩或 Esc 收起。
桌面展开偏好跨岗位沿用，窄屏抽屉不覆盖该偏好。切换员工和恢复上次对话不会自动展开
员工下面的会话；桌面导航保持原状态，窄屏选中后收起抽屉。会话行提供
「归档」：历史完整保留，归档后移入该员工的「已归档」列表，可查看和恢复。运行中的
会话需等回合结束再归档。归档状态保存在员工工作区的 `.dsemployee/session-archives.json`，
刷新和更换设备后仍然保留；Hub 和员工节点均需升级以支持归档接口。

「员工配置」分为员工设置、共享模型服务和节点设置。员工设置左侧选人，右侧分为模型、
基本信息、审批与权限；手机使用员工选择器。配置选择与聊天中的员工独立，切换员工和
分区会保留本页未保存的表单草稿，刷新页面后草稿不保留。模型切换会明确说明新会话默认
与当前打开会话的生效范围；运行中的会话不会自动等待切换。

「批量设置模型」支持筛选、多选、全选或仅选在线员工。选择服务、模型及显示名称后可
一键应用，并可设为新会话默认模型。相同服务与模型复用已有条目并保留原显示名称，其他
模型保留；不会批量改写历史会话。逐员工展示成功与失败原因，可只重试失败员工；离线
员工需上线后重试。当前打开的会话只有勾选相应选项才一起切换。

控制台在本浏览器按 Hub 保存最近读过的会话列表和历史副本（最多 20 位员工的列表、8 个
会话，每会话最多 800 个事件，总序列化文本不超过 100 万字符）。员工节点暂时离线时，
可以回看这部分记录；未缓存的历史仍需节点在线。浏览器禁止存储或容量不足时，正常联网
读取仍可使用。新定时任务首次派发会创建自己的会话，后续复用；已有任务的会话绑定保留。

控制台里有一张「**体检**」卡片（默认收起），把三类**不会报错**的问题主动摆出来：

| 体检项 | 判据 | 为什么它值得一个专门的地方 |
|---|---|---|
| 控制台脚本 | 本页脚本指纹 vs 服务端印在页面上的指纹 | 不一致 = 本页跑的是被 PWA 缓存冻住的旧脚本（"手机和电脑不一样"的经典成因） |
| 节点代码 | 每个节点上报的代码指纹 vs Hub 自己的 | 节点是手动升级的：跑旧代码时界面上一模一样（照常在线、照常列员工），只是能力缺失。`unknown` = 老节点没上报，**不当作一致** |
| 员工工作区 | 缺 `.git` 锚点 + 有私有技能 | dsh 的 `projectRoot` 只认 `.git`：工作区没有锚点时，写在 `.dsh/skills` 里的私有技能会被**静默忽略** |

### 5. 创建一个数字员工
> Windows 上建议用 `--params-file` 而不是行内 JSON——PowerShell 会把参数里的引号吃掉。

```bash
node bin/dse.mjs rpc employee.create --params-file create.json \
  --hub ws://127.0.0.1:19790/ws
# create.json: {"nodeId":"<节点id>","name":"小艾","role":"负责每周整理周报与数据核对","group":"运营组"}
# group 可选（≤64 字符）：控制台办公区视图按它分区；省略则归入「未分组」
# intro 可选（≤500 字符）：初始提示词，一句话身份/设定，每次会话开头注入
```

节点上会生成：

```
D:\Employees\xiao-ai\
├── .dsemployee\employee.json    员工身份与元数据（分组、intro）
├── AGENTS.md                    岗位说明书 + 知识库（dsh 每次会话自动注入）
└── .dsh\skills\                 该员工专属技能（dsh 扫描 rank 100，优先级最高）
```

也可以直接在控制台办公区的「新建员工」折叠卡里建（名字/岗位/分组/落在哪台节点）。

### 6. （可选）给某个员工单独配模型端点

控制台「模型配置」标签页按分组列出所有员工；展开某个员工即可配置 **OpenAI 兼容端点**
（API URL + API Key + 模型）：填好 URL 和 Key 后点「获取模型列表」会从端点的 `/models`
拉取可用模型供选择（节点直连端点，不经 dsh）。

- 端点库配置存 Hub 的 `llm-endpoints.json`（0o600），员工工作区的 `.dsemployee/llm.json`
  只保存员工对端点库条目的引用与模型选择；apiKey 出接口一律只回掩码，并会在员工所在节点
  再落盘一份供 dsh 使用。Hub 与节点之间的传输属于敏感链路——生产部署务必走 Tailscale/TLS
  （见下文部署小节）。
- 保存即接线到 dsh：按员工声明 `dse-emp-<id>` 的 pi-ai provider 路由并写入凭据；
  该员工**新建**的会话自动选到这条路由的模型。已存在的会话不迁移。
- 「清除配置」会同时删掉 provider 声明与凭据，新会话回落到节点默认模型。

### 部署到云服务器（阿里云等）

Hub **认证调用方但不加密传输**。绑到公网网卡意味着设备令牌、会话内容、员工输出全部
明文过网——所以非回环绑定必须显式加 `--allow-non-loopback` 才起得来，而正确做法是给
传输层补加密，二选一：

- **Tailscale（推荐）**：服务器与终端都装上 Tailscale，Hub 绑回环或 `100.x` 地址
  （`--host 100.x.y.z --allow-non-loopback`），控制台经 `http://100.x.y.z:19790/` 访问。
  流量走 WireGuard 加密，且天然不暴露公网。
- **TLS 反代**：nginx/caddy 终止 TLS 后转发到回环的 Hub（WS 升级头要转发），控制台用
  `https://` 打开。**反代部署必须给 Hub 加 `--trust-proxy`**：不加的话所有连接的客户端
  IP 都是回环地址，节点配对的自动批准闸（`fromLoopback`）会把互联网流量当成"本机节点"
  直接放行。只有反代是你自己控制的（并且它会覆盖而不是透传 `X-Real-IP`/`X-Forwarded-For`）
  时才开；直连部署开了反而把伪造面引进来。生产建议用 systemd 托管（把 `--trust-proxy`
  写进 unit 的 ExecStart——该选项不落盘，重启即失效）。

> 注意：浏览器只在**安全上下文**（https 或 localhost）里提供 WebCrypto。纯 `http://` +
> 裸 IP（非 Tailscale/内网域名证书场景）打不开控制台——授权页会给出提示。

## 安全模型

- **身份**：`deviceId = sha256(SPKI DER)`，即公钥指纹。密钥只有 32 字节。
- **握手**：服务端下发一次性 nonce → 客户端用私钥签规范 JSON（键顺序固定、scopes 排序）→
  服务端验签 + 校验时钟偏移 + nonce 一次性。
- **配对**：新设备默认必须人工批准。主路径是 6 位配对码（Hub 启动时打印或终端节点就近
  生成，只存 sha256、一次性、限时就作废，连错 5 次按 IP 短暂封禁）；兜底是 Hub 本机
  `dse pair approve`。自动批准只在"回环/白名单 + `role: node` + 未索要任何 scope + 首次"
  四个条件同时满足时发生。
- **令牌**：Hub 只存 sha256。任何签发/轮换的 scope 都**不能超出该设备配对时批准过的集合**
  （`scopesExceeding` 强制）。
- **权限**：方法 → scope 的映射集中在 `src/protocol/methods.ts` 一处；未知方法一律拒绝；
  有副作用的方法强制幂等键；事件广播按 scope 门控，未知事件族不投递。
- **机密边界**：LLM apiKey 会以 0600 权限保存在 Hub 端点库，并同步到员工所在节点供 dsh 使用；
  所有 API 返回值一律只带掩码。生产部署必须保护 Hub 磁盘与 Hub↔节点传输链路。
- **工作区边界**：所有来自网络的文件操作先过 `isPathInside`，`..`、绝对路径、符号链接
  逃逸都被拒。
- **dsh 永不暴露**：`/api` 只被同机的节点代理经回环访问。
- **preset 即代码**：dsh 的组合文件里 `!!js` 会执行，上游把 `$DSH_HOME/.agent-presets`
  的信任级等同于 shell 访问，并刻意拒绝任何调用方提交组合文本。本工具**不再**物化
  每员工 preset（技能私有层由 dsh 默认发现提供），这条不变量请继续守着：
  **Hub 侧来的数据绝不允许流入组合 YAML**。

## 安全提示（务必读一遍）

- **不要为了图省事关掉设备配对鉴权。** 允许不安全认证、放宽来源白名单、把公网域写进白名单 ——
  这三样只要凑齐，"配对是一等契约"就作废了，而它正是这套系统唯一的准入闸门。开发期嫌麻烦就用
  回环地址，别动鉴权开关。
- **本 Hub 认证调用方，但不加密传输。** 因此非回环绑定必须显式确认才允许启动；对外暴露
  请前置带 TLS 的反向代理（并加 `--trust-proxy`），或走 SSH / WireGuard / Tailscale 隧道。
  员工的 LLM apiKey 配置经 Hub 转发到节点也属于这条传输路径——只有 Tailscale/TLS 覆盖时
  它才安全；Hub 端点库与节点工作区都会以 0600 权限保存，务必纳入磁盘权限与备份管理。
- **dsh 的 `/api` 永远不要暴露到网络。** 它只有防 DNS 重绑定的可达性栅栏、没有认证层，
  官方也因此刻意禁止 `dsh web --host 0.0.0.0`。本项目让节点代理在同机经回环驱动它。
- **凭据与私钥不要进版本库。** 本仓库的 `.gitignore` 已覆盖 `.dshdev/`（含模型凭据）、
  `.dse-*/`（含设备私钥与令牌）；克隆后请勿改动这几条。
